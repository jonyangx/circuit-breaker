# Stakeholders Analysis：Circuit Breaker

| 利益相关者 | 角色 | 关注点 | 影响力/优先级 |
|------------|------|--------|--------------|
| 中间件/平台开发工程师 | 集成方（Primary Actor） | 极致性能、零分配、无锁、低依赖、API 简洁（tryAcquire/release） | 高——直接使用者 |
| 业务开发工程师 | 集成方 | 接入简单、不破坏现有调用链、可靠降级（不误杀） | 高 |
| SRE / 运维 | 观测方 | Prometheus 指标（pass/block/EWMA 健康）、过载保护、可热调参 | 中——线上稳定性 |
| 被保护服务的终端用户 | 间接 | 服务可用性、低尾延迟（治理组件不拖慢正常请求） | 中——价值最终受益者 |
| 性能基准/质量工程师 | 验收方 | JMH 纳秒级 + 零分配回归红线不破 | 高——守住核心价值 |
| 架构师 | 决策方 | 架构一致性（flat execution / config-state 分离 / 无治理定时线程） | 高 |

## 关键诉求与冲突裁决

- **"不误杀" vs "极致性能"**：令牌桶刻意不分段（保留全局 QPS 不变量），宁可承受超高 QPS 下单 AtomicLong 的 CAS 重试成本，也不为性能牺牲正确性（design §4.2）。→ 裁决：正确性优先。
- **"功能丰富" vs "纳秒开销"**：明确排除集群限流/热点参数/配置中心监听器，避免破坏无锁与零分配不变量。→ 裁决：性能优先，复杂功能外置。
- **"实时精准面板" vs "无 LeapArray"**：放弃 Sentinel 式秒级精确面板，改用 LongAdder 单调计数 + scraper 算差值。→ 裁决：观测让位于热路径性能，但提供轻量 Prometheus 暴露。
